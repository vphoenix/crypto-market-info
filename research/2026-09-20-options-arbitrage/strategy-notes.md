# 期权套利：策略、收益币种与可成交数据要求

研究日期：2026-09-20。范围为公开数据与离线筛选，不涉及交易、账户或下单。下列优先级是对数据研究价值的判断，不代表已验证存在可盈利机会。合约和费用事实来自文末附近链接的官方资料；公式为按合约收益自行推导。

## 应先抓什么

| 优先级 | 候选 | 关键数据 | 为什么适合先做 |
| --- | --- | --- | --- |
| 1 | 同所、同结算规则的 call/put + 同到期交割期货 | 两个期权与期货的同步可执行深度、乘数、资金成本、结算规则 | 三腿；有明确终值恒等式，可以区分理论偏离与真正可成交边 |
| 1 | 同到期垂直价差、蝶式，及已有公开 combo 盘口 | 相邻行权价的双边盘口、原生组合报价、组合腿定义 | 不用拟合波动率曲面即可检查部分无套利约束；组合报价可能减少价差与执行风险 |
| 2 | 同所 box 及合成融资曲线 | 四腿盘口或原生 box、可用资金利率、保证金规则 | 同时作为套利筛选和融资价格数据；四腿费用与占资通常更苛刻 |
| 3 | 跨所相似期权价差 | 双所盘口、各自指数/结算窗口、汇率、独立保证金 | 先当相对价值候选；合约看似相同，实际终值经常不一致 |
| 4 | IV、skew、期限结构、买波动/卖波动 | 全链报价、历史成交、指数与期货、动态对冲成本 | 可以产生研究信号，但不是静态无风险套利 |

先覆盖 BTC、ETH 的短至中近期限、ATM 附近及相邻行权价，再根据真实双边深度扩大。建议先把“适中期限”作为分层，例如 2–45 天，而非永久白名单；0–2 天、远翼与长到期保留在低成本发现层，若有充足双边深度再升档。极虚值便宜权利金不等于便宜交易：最小 tick、费用上限、空 bid 和最小数量会主导结果。精确期限、delta/moneyness 范围必须由覆盖率与可执行容量实测调整。

## 1. 先固定合约语义，再计算价差

以下 `X` 是到期结算指数，`K` 是行权价，所有腿到期时间、指数和结算窗口一致。公式以一单位基础资产名义为例；实际须按合约乘数和可交易 lot 缩放。

线性期权在报价币中的终值为：

```text
call = max(X-K, 0)
put  = max(K-X, 0)
call - put = X-K
```

Deribit USDC 期权为欧式，现行规则在 ITM 到期时先生成行权价上的同到期期货，再立即现金结算为 USDC，净收益仍等于上述线性公式。该规格还明确：每个期权到期日同时列出对应期货；必须实际检查该期货有可交易深度。对应期货与期权生成头寸的净额会影响交割费，不应简单重复计费。[官方线性期权规格](https://support.deribit.com/hc/en-us/articles/31424932728093-Linear-USDC-Options)

反向、币本位期权的币终值为：

```text
call_coin = max(X-K, 0) / X
put_coin  = max(K-X, 0) / X
call_coin - put_coin = 1-K/X
```

Deribit BTC/ETH 反向期权权利金与结算使用相应币，合约代表相应基础资产数量；到期按 07:30–08:00 UTC 指数 TWAP 结算。网页上的美元显示价和 IV 都不能替代实际币报价盘口。[官方反向期权规格](https://support.deribit.com/hc/en-us/articles/31424939096093-Inverse-Options)

对比平台还应确认：OKX BTC 期权一张代表 0.01 BTC，ETH 一张代表 0.1 ETH，币本位结算。[OKX 期权规格](https://www.okx.com/help/whats-options-trading)

OKX 2026-03-06 公告明确自 2026-03-18（UTC+8）起，将到期结算采样窗由一小时缩为最后 30 分钟，每 200ms 采样一次。上述规格页即使显示较新的更新时间，正文仍残留一小时旧口径；应以明确生效公告维护规则版本。当前不能再用“OKX 一小时、Deribit 半小时”解释跨所差异；指数成分、具体采样、异常规则等仍须匹配后才能认定相同终值。[OKX 结算规则调整公告](https://www.okx.com/en-us/help/okx-announcement-on-the-adjustment-to-the-calculation-method-of-delivery)

应保存 `base_asset`、`quote_currency`、`premium_currency`、`settlement_currency`、`payoff_type`、`option_type`、`strike`、`expiry_time`、`contract_multiplier`、`quantity_unit`、`index_id`、`settlement_window`、规则版本与生效时间。禁止仅按 `BTC + 日期 + K + C/P` 连接跨所记录。

## 2. Put-call parity：分别处理线性与反向

### 线性：call + short put + short future

同一单位基础资产的线性期货空头从 `F` 建仓，到期累计收益为 `F-X`，故：

```text
long call + short put + short future => (X-K)+(F-X) = F-K
```

可执行两方向的费用前到期边为：

```text
E_long_synthetic  = F_bid - K - H(C_ask - P_bid)
E_short_synthetic = K - F_ask - H(P_ask - C_bid)
```

`H(d)` 是初始净支出到期后的资金成本：`d>=0` 时使用真实可锁定借款成本或自有资金机会成本；`d<0` 时，只对可支配的净收入使用可实现投资收益。保证金占用的期权收入不能默认投入其他收益产品。零利率只是初筛特例，此时 `H(d)=d`。理论关系 `C-P=D(F-K)` 同样依赖资金/结算假设；逐日盯市期货还需计入中间现金流的资金成本。

还要扣每腿交易费、实际扫单滑点、交割费、保证金资本成本及对冲数量舍入残差。若只有 perpetual，可研究对冲后的期限基差，但未来资金费及终止基差未知，不能把上述到期恒等式沿用为锁定套利。

### 反向：对冲的 USD 名义应为 K，而非随手取一张期货

USD 名义为 `N` 的反向期货多头，从 `F` 到 `X` 的币收益为：

```text
N * (1/F - 1/X)
```

所以对应一单位基础资产的反向期权，买 call、卖 put，并卖出 `K` USD 名义的反向期货：

```text
(1-K/X) + K*(1/X-1/F) = 1-K/F  [单位：币]
E_long_synthetic_coin = 1-K/F_bid - H_coin(c_ask-p_bid)
E_short_synthetic_coin = K/F_ask-1 - H_coin(p_ask-c_bid)
```

这里大写 `C/P` 是线性报价币权利金，小写 `c/p` 是币权利金。利润币种固定后再比较收益率；正的固定 BTC 收益并非固定美元收益，原有 BTC 抵押资产本身也有美元价格风险。

Deribit 反向 BTC 期货一张是 10 USD，ETH 一张是 1 USD；API 的反向期货下单数量使用 USD 名义。`base_currency=BTC` 不代表 `contract_size=10` 就是 10 BTC。`K × 基础币数量` 必须符合期货最小数量与步长，否则余下的价格敞口单列。[官方反向期货规格](https://support.deribit.com/hc/en-us/articles/31424938981533-Inverse-Futures)

## 3. Box：固定的是哪一种货币

`K1<K2`，买入 box 为：

```text
+ call(K1) - call(K2) + put(K2) - put(K1)
```

线性 box 到期支付 `ΔK=K2-K1` 单位报价币。买入成本用 `ask(C1)-bid(C2)+ask(P2)-bid(P1)`；卖出收入用相反方向的真实盘口。买 box 候选须满足到期收款减去初始成本的融资终值、费用和资本成本仍为正；反向卖 box 则使用实际可支配收入的投资终值减去 `ΔK`。不能把买卖资金利率设成同一个无风险常数。长 box 的隐含利率高于普通存款，可能补偿占资、流动性或平台风险。

反向币本位 box 到期支付 `ΔK/X` 币，等值固定 `ΔK` 美元，但不是固定币收入。若增加 `ΔK` USD 名义的反向期货多头，终值成为：

```text
ΔK/X + ΔK*(1/F-1/X) = ΔK/F  [单位：币]
```

这可构造固定币终值，但多了一腿、费用和保证金。不能把币报价 box 成本直接与美元 `ΔK` 比较，也不能只用当前现货价换算便宣称所有未来币风险均消失。

## 4. 垂直价差与蝶式：不用 IV 模型的检查

同到期、同结算规则，以下组合的毛终值非负，线性与反向币本位均成立：

```text
call vertical: +C(K1)-C(K2), K1<K2
put vertical:  +P(K2)-P(K1), K1<K2
equal-strike-spacing butterfly: +C(K1)-2*C(K2)+C(K3)
                               K2-K1 = K3-K2
```

例如 `ask(C1)-2*bid(C2)+ask(C3)<0` 是负成本买入非负毛终值蝶式的初步信号。中间腿需要双倍数量，容量不能取三腿最小显示量后忽略系数。非等距行权价须用 `λ=(K3-K2)/(K3-K1)`，检查 `λ*C1+(1-λ)*C3-C2`，并转成可成交整数比例。

线性垂直价差终值上限是 `ΔK`，其价格上界需与同币种 `ΔK` 的可获得贴现值比较。反向币本位上限是状态相关的 `ΔK/X`，不能使用 `ΔK` 个币作为界限。毛终值非负并不保证费用后非负，尤其多腿行权费、独立腿成交与强平会破坏简单结论。

最值得额外采集的是原生 combo 的真实盘口及其腿定义。Deribit combo 可一次执行多腿；组合簿会创建、失活，不能只在进程启动时发现一次。只有一个组合内的腿具备这种同时成交语义，组合之外的期货/现货对冲仍有分腿风险。[官方 Combo Books](https://support.deribit.com/hc/en-us/articles/31424954956061-Combo-Books)

## 5. 费用、保证金与“可成交”的边界

费用规则要单独定类型并版本化，记录费率基数、费用币种、maker/taker、权利金 cap、日到期豁免、组合折扣、来源与生效时间。公开费率只能做可复核的账户等级情景，不能假装知道用户实际等级。

Deribit 公开费率表的 Standard 期权费为 3 bps、cap 为权利金的 12.5%；含买卖方向的合格期权 combo，买方向和卖方向费用总额较低的一侧免除。BTC/ETH 日到期期权有交割费豁免；普通期权交割费与 cap 要另算。页面存在“upcoming fee levels”措辞，因此生产费率应连同生效时间证据核对，不能仅硬编码表值。[Deribit 费用](https://support.deribit.com/hc/en-us/articles/25944746248989-Fees)

Bybit 当前页面为 USDT 期权，普通等级 maker/taker 为 2/3 bps，交易费 cap 为权利金 7%，交割费 cap 则为 12.5%；BTC/ETH 交割基础费为 1.5 bps，日到期豁免。旧链接仍可能展示旧币种与旧 cap，抓取时必须核对新页面与市场元数据。[Bybit 当前期权费用](https://www.bybit.com/en/help-center/article/Bybit-Option-Fees-Explained)

需要区分三种结果：

1. **理论约束偏离**：使用 mid/mark，或只满足毛收益恒等式；适合质量排查与选池。
2. **同步盘口净边**：各腿有效、深度足够，使用买 ask / 卖 bid 和费用模型；仍不保证真实同时成交。
3. **有可复核执行条件的候选**：再满足组合原子性或保守延迟压力、数量步长、资金与保证金约束，且费用/结算风险有明确界限。

按到期指数比例计算的线性交割费可能随 `X` 改变，毛终值恒定并不意味着净终值恒定。若只按一组压力场景估费用，应标为“场景下正净边”，不能写“已锁定无风险收益”。保证金减免也不能由经济上的对冲自动推出；跨平台至少有两套独立资金池。费用后利润应同时除以实际占用资本与持有时间，短期年化不能代替绝对利润和容量。

## 6. 把数据采集变成机会筛选的依据

- 所有腿同时保留交易所时间、接收时间、连接/连续性状态、book version、有效性与实际深度。冷门期权长时间无更新可以是真实有效静态盘口，不能一律按报价年龄判失效；需结合连接心跳、连续性和重新快照确认区分。
- 广覆盖链摘要只用于发现：有双边价、可用深度、距到期、moneyness、最近成交、价差/tick、与期货偏离。候选全组升档，而不是只升档便宜的一腿。
- 主历史对新数据按每秒前 10 档落库并写 `stored_depth=10`；旧 50 档分钟继续按其 `stored_depth` 完整回放。若要研究 100–500ms 的机会，分析层须另设计定类型候选观测，记录必要腿引用、源/接收时间、使用价量或扫单结果、费用版本与有效性；不增加另一套秒内 L2 快照/差量历史。有界协议探针的原始消息只作研究证据。1 秒聚合快照只能支持 1 秒尺度结论，不能恢复秒内先后关系。
- 切勿把逐合约 REST 轮询结束后的结果当作同一时点快照。优先 WebSocket 同时维护各腿，候选计算记录最大接收时间差、各腿源时间与模型输入版本。
- 先输出可执行容量曲线而非一个价差：对不同基础资产数量计算各腿扫单 VWAP、最小净边、成本分解、预计资本、余留敞口。`qty_lot` 先转成一致基础币名义。
- 统计候选持续时间、延迟 100/250/500/1000ms 后存活情况、同期成交是否支持、真实双边容量和拒绝原因。全部延迟只是研究情景，最终阈值须依据实际采集和预期执行链路测得。
- 选池以“扣除成本后仍可成交的数量 × 可观测持续时间”与数据完整性排序；不以最大 mid 偏离、最高年化或最多 symbol 数排序。低频规则来源失败不能沿用旧规则并伪装为当前已核验。

## 7. 不应称为静态套利的信号

- 高 IV 卖出、低 IV 买入，或 delta-neutral straddle：仍有 gamma、vega、跳跃和离散对冲风险。
- 两所相同行权价、到期时间的期权价差：指数、结算窗口、币种或合约乘数不一致时存在终值残差。
- 用永续代替同到期期货的 conversion：未来 funding 与终止基差未锁定。
- box 收益率高于某个宣传 APY：后者可能有额度、退出、浮动利率和风险差异，不能直接作为可锁定融资成本。
- 用 mark、index、交易所 IV、last 或用户自己打算挂出的 maker 价格计算出的正边：缺少当前可成交证据。

建议报告默认称“候选价差/约束偏离”，同时保存为何尚未达到更强证据等级。真正提高命中率的办法是扩大有效同步配对、增加原生组合报价和资金/规则数据，然后按成本与容量过滤；不是忽略限制多报机会。
