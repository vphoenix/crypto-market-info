# 现货、期货5档与 OKX 配对全范围采集

2026-10-07 按用户方案4实现：新现货、永续、交割期货每侧5档，期权每侧10档；补齐此前容量估算中的 OKX 可借贷 USDT 现货/永续配对。10月7日仅交付代码，10月8日已按用户要求部署到正式采集服务；当前状态及验证见[部署记录](../research/2026-10-08-okx-five-level-deployment/report.md)。后续独立预测、完整分钟成交量和资本规则采集见[找币数据衔接](discovery-trading-contract.md)。

## 采集范围与衔接

`MARKET_BOOK_DEPTH=5` 为默认，支持10档回退。Deribit 交割期货沿用该配置，期权固定10档。源协议仍维护完整本地 L2：OKX books 400档，Binance/Bybit原有深度；先截目标深度再按价格计算秒级最终差量。零数量删除、无变化秒、断线无效秒语义保持。

`OKX_PAIRED_ENABLED=true` 启用独立配对模块，不受跨交易所“至少两家共有”规则限制。它调用公开 SPOT、SWAP、MARGIN 三种产品目录与公开借贷政策，选择 live、normal、crypto 类别1、USDT报价现货/杠杆产品及同基础币 USDT结算线性永续，且公开基础借贷额度为正的完整交集。2026-10-07 公开接口核验为167对，含已有 BTC，两腿共334条；当前手动5条主行情中已有 OKX BTC 两腿，实际增加332条。币种列表不写死，30分钟复核新增与退出。

四个来源全部成功且严格解析才构造候选目录，空结果、冲突身份、缺字段和超过容量均拒绝，不截取前若干币种。单次失败继续原有集合，下一分钟重试。由于公开接口不是原子快照，四次请求分别保存请求/接收时间与 SHA256，供研究端判断新鲜度与一致性。

新集合通过同一个数据库注册器分配 instrument ID；共享注册锁避免与期权注册并发抢号。已有手动行情保持原采样所有权，配对模块只采集其余腿，避免重复 writer。tick、lot、合约乘数或版本改变产生新身份。注册定义不代表已获得有效行情。

新增集合在独立 L2 状态预热，全部书就绪后提交未来 UTC 分钟生效目录，再在同一分钟替换采样源。旧书采样完成旧分钟后切换，新书第0秒建立5档起点。首次启动的 sampler 使用显式分钟边界，避免跳过第0秒。切换后停止旧代；失败、断线和序列断档不冒充有效数据。目录只代表预期集合，实际有效性必须同时检查该分钟 `valid_bitmap`。

OKX 现货与永续使用同一 books 分片，最多20频道/连接，保持序列检查、重连快照和有界队列。容量预算计入主行情及预热期间同时存在的两代 WS/缓冲，采样源、永续、连接、消息槽、文件描述符与两分钟写队列均设上限。默认最多256对、128条总 WS、1100条现货/永续源；超过上限明确拒绝新增集合。

## 保存的数据

主价格事实继续写 `order_book_minute` + `order_book_second_delta`，新数据显式 `stored_depth=5`；不重写、删除或截短旧10/50档历史。查询必须按每分钟实际深度加载全部起点并应用差量。物理50列与列默认值50保留，以兼容旧 writer。期权/交割事实继续原 derivative 三表与原批次提交协议，约束允许5/10，writer禁止把期权降成5档，哈希编码域不变。

新增 `okx_public_loan_policy` 和 `okx_paired_catalog` 两张定类型观测表。产品元数据保存为 instrument 定义及配对最小下单量，四个来源的时间、URL、payload hash写入目录。公开借贷政策按分钟保存 basic 每日费率/公开额度、币种特殊费率及 vip/regular/config 的公开条款。空的额度、弃用折扣等保存 NULL。费率、金额、系数全部 Decimal(38,18)；源响应只在内存解析，事实入库，不另建 JSON 备份文件。

目录 UUID 引用已提交的借贷观测，提交和读取时核对第四来源的 URL/hash/时间及币种正额度。查询验证规范化行摘要，未来生效目录不可提前用于筛选。写入重试复用 UUID 和事实值。

公开额度是参考限制，不是账户实时库存；级别额度系数不是分档边际利率。交易程序仍须通过自己的实时账户接口复核实际费率、额度和下单权限。该项目仍只做公开数据采集。

所有新增永续复用已有资金费率 WebSocket、整点估算与结算后串行确认。配对模块使用父生命周期的单一整点采集器，按生效集合选择估算源，先冻结整批估算再写入，避免换代漏整点或取消未写完的记录，不将资金费率混入借贷收益。公开借贷接口限速按每次物理请求执行（至少1.1秒间隔，含重试），两条后台链路共享限制。本次不增加分钟成交量采集，也不改变既有资金费率估算的整点落库频率。

## 配置、验证与部署边界

| 配置 | 默认 | 含义 |
|---|---|---|
| MARKET_BOOK_DEPTH | 5 | 现货/永续/交割期货；只允许5或10 |
| OKX_PAIRED_ENABLED | false | 开启 OKX 同站配对扩容；仓库生产模板设true |
| OKX_PAIRED_MAX_PAIRS | 256 | 1–500，完整范围超限拒绝 |
| OKX_PAIRED_REFRESH | 30m | 目录复核，最短1分钟 |

`collector -print-okx-pairs` 只读检查四个公开接口，不连接数据库。实际守护服务的 env 来自已安装 unit，不会因仓库模板修改自动更新。

验证包括5档一分钟60秒精确回放、深档进入前5档、同秒多次更新最终值、无变化与无效区间、分钟边界换源、混合5/10/50历史真实 ClickHouse 读写、期权10档与交割5档、混合现货/永续订阅、严格小数和完整来源、NULL条款、稳定重试身份与引用来源绑定。完整测试、真实公开采集及容量测量结果保存于 `research/2026-10-07-five-level-okx-pairs-implementation/`；独立审核见同目录审核记录。

部署必须单实例停止旧采集器后安装，并核验完整目录、两腿有效秒和 `stored_depth`。只改深度会降低后续增长，不影响历史磁盘占用。本轮没有部署操作，也没有运行自动交易。
