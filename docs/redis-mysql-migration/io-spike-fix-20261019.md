## Redis：延后整理，不减少交付保障

`auto-aof-rewrite-min-size` 从 64 MiB 提高至 256 MiB，`auto-aof-rewrite-percentage` 从 100 提高至 400。两项条件同时满足才触发，不是固定每几分钟重写；基准较小时由最小大小限制，基准较大时由增长比例限制。

保留 AOF、`appendfsync=everysec`、`no-appendfsync-on-rewrite=no` 和原 WAITAOF/本地 spool 交付流程。配置文件与在线 CONFIG SET 一致，无需重启 Redis。允许 AOF 暂时增大，以减少重复写出当前状态；它不是硬性文件大小上限，队列增长、重写执行时间和失败均可能使文件更大。

## MySQL：追加记录与窄身份索引

候选实现新增三张独立运行时表：`source_publication_intents_v2`、`source_batch_status_v2`、`public_observation_provenance_v2`。逻辑字段、哈希、完整来源、首次知晓时间、发布条件和物理重复检测保持原义。

旧布局把完整记录按 SHA-256 主键分散存放；候选使用内部自增的 8 字节 `_storage_id` 组织追加页，以唯一索引 `immutable_identity(_key_hash[, _occurrence])` 检查原身份。该内部序号没有业务含义，不参与来源 ID 或内容摘要。原业务检索索引保留，其主键后缀缩短；同时新增唯一身份索引的空间与写入成本必须计入性能对照，不能只报告数据页变小。

新写入仍要核验旧历史：旧表使用现有业务身份索引查找完整身份，只有命中时才取旧完整记录；新表也参与同一事务中的核验。不以缓存中的“未找到”替代数据库约束。读取使用同一语句快照的 UNION ALL，并在两分支和合并结果上应用原条件、排序与 LIMIT；保留重复物理行供领域校验拒绝，不用 UNION 去重掩盖歧义。

写入开关为 writer `--source-storage-v2`、collector `MYSQL_SOURCE_STORAGE_V2=true`。安装完整扩展后，新版客户端无论写开关是否开启，都读取新旧两种格式；每个任务的 `WithProducer` 继承该能力。管理入口为 `storage-migrate install-source-storage --family crypto_market_info --target <明确数据库> ...`。旧表和冻结迁移映射不重写，生产安装只创建空扩展表及 schema 登记。

回退必须保留兼容读取的新二进制，停止相应写入进程后关闭新写开关再启动；不能回退到不认识新表的旧二进制。队列、producer generation/holder 和历史记录保留。

具体写入回退：先正常停止主 collector 和 writer，将两个 unit 的 `95-source-storage.conf` 移到各自 drop-in 目录之外，执行 `systemctl --user daemon-reload`，再先启动 writer、后启动 collector。保留现有 `90-quality-storage.conf` 和当前二进制；新来源表仍被读取和核验，不删除扩展表。Redis 可独立回到 64 MiB/100%，但必须同时修改 `deploy/storage/redis.conf` 和在线值，不能用重启清队列代替配置回退。

## 内存与换入

本轮开始宿主机可用内存约 2.9 GiB；MySQL RSS 约 2.48 GiB，swap 约 496 MiB。Redis RSS 约 193 MiB、swap 约 4 MiB；主 Codex RSS 约 268 MiB、swap 约 113 MiB。已有交换页不等于当前正在耗尽内存。没有依据为了消掉 swap 数字而强制 swapoff，也没有盲目扩大 2 GiB MySQL buffer pool。

编译与隔离验证限制并行度；隔离 MySQL 只在验证期间启动，最终恢复原配置和停止状态。最终生产采样需排除该实例的活动。

`live-attribution.py` 增补系统可用内存、换出、关键进程 RSS/swap 以及约每 30 秒的 Redis AOF 计数/大小/配置。今后一次采样即可区分正常追加、文件重写、旧交换页和新换页事件；该脚本本身仍只读，不自动调参或启停服务。
