# 期权数据取舍：以套利机会研究为目标

日期：2026-10-07（北京时间）。本文记录实施前的分析与取舍建议；用户随后授权的无损辅助存储精简及旧副本删除已完成，见[清理记录](../../../research/2026-10-07-options-redundancy-prune/report.md)。有损诊断裁剪、降档、降频及新增经济输入未实施。本次只讨论期权及其配套交割期货、指数；其他采集类别不在本次范围。

## 1. 结论

当前期权采集存在两个问题：用于证明采集过程的记录保存得过重；直接决定净收益的费用、结算和资本占用输入仍不完整。应保留可成交价量、经济规则与最低必要质量信息，减少重复状态和长期排障明细，并补少量关键经济输入。

“现有程序会读取某列”只说明改造有兼容工作，不等于该列值得永久保存。当前 quality、evidence、commit 都有真实消费者，不能直接删表后继续使用原查询；应该先替换数据契约和查询依赖。

本轮建议优先支持同所同到期平价、box（箱式组合/隐含融资）及跨行权价无套利边界研究。普通期限价差、波动率和动态对冲策略另有风险及数据需求，不把其全部潜在字段列为当前必采项。

## 2. 用哪些数据回答哪些收益问题

| 研究目标 | 最低输入 | 判断边界 |
|---|---|---|
| Call＋Put＋同到期期货平价 | 各腿同刻有效 bid/ask 与数量、同到期/币种/结算条件、strike、数量单位、费用与融资成本 | 能先做毛利排除和净边初筛；不同币种或终值语义不能直接相减 |
| Box、合成借贷 | 同到期四腿价量、两行权价、终值币种、期限、融资成本、资本占用及结算费 | 正的隐含利率并不自动是套利利润；须比较自有资金机会成本/借款成本，以及可支配现金和保证金 |
| 垂直价差、蝶式的无套利边界 | 同到期多行权价价量、腿比例、下单步长、费用 | 可筛终值非负而入场净成本为负等条件；一般“便宜”组合不等于无风险 |
| 跨到期相对定价 | 各期报价、期货/指数、融资曲线和结算条件 | 不同到期的现金流不能直接抵销，不能仅凭远近月价格排序断言套利 |
| 波动率/偏斜/动态对冲 | 期权与标的历史、可成交对冲报价、费用、模型/波动路径，按用途增加成交和模型指标 | 承担模型、波动和路径风险；当前静态筛选不要求全量 IV/Greeks |
| 跨所期权套利 | 多所可比终值产品、同时刻价量、各自结算指数/窗口、费用、资本和兑换路径 | 当前期权持续采集仅 Deribit BTC/ETH 币本位及 USDC 四族，不能称为跨所或全资产期权覆盖 |

过去实际研究用到的是 bid/ask、深度、有效性、合约规格及指数，主要计算 conversion/reversal 和 box。参见 [2026-10-02 研究](../../../research/2026-10-02-opportunity-review/options/report.md)及 [all_seconds.py](../../../research/2026-10-02-opportunity-review/options/all_seconds.py)。这类研究可以用负毛利排除组合；正毛利仍需要完整成本和资金口径才能进入收益率排名。

## 3. 必须长期保留的信息

| 数据 | 保留方式与原因 |
|---|---|
| 期权、配套交割期货的实际买卖价和数量 | 保留每秒可回放历史，用买入 ask、卖出 bid 计算成本和容量；不能用 mark、中间价代替 |
| 合约定义 | 标的、C/P、strike、到期、结算币、linear/reversed、数量单位、乘数、指数及结算规则版本；稳定定义存一份，变化建版本 |
| 下单规则 | 最小下单量、数量步长、tick/分段 tick、知悉和生效时间；决定算出的组合能否按腿比例下单 |
| 原始行情时间、接收/可知时间、采样秒 | 用于跨腿对齐、防止未来信息；连续无行情更新不自动等于断流。时间可差分/变化编码，但不能伪造刷新 |
| 有效、缺失、已知空簿/空边、市场已知/开放及原因 | 区分没变化与没采到，防止用断线旧 Call 拼接新 Put 制造假机会；位图和状态区间足够廉价 |
| 目录覆盖、新增、退役及规则/市场状态历史 | 知道该时段本应采哪些合约，区分未采、失效和确实没挂单；继续自动发现新合约 |
| 必要来源和写入完整性 | 每次低频观测保留来源、时间和 payload hash；分钟发布及预期成员/差量完整性防止半批数据进入分析 |
| 对应指数 | 共享保存实际观测，用于币种换算、合约估值及结算核验；指数不是可成交换汇报价 |

盘口按合法单侧使用：没有 bid 的期权仍可能是组合的买入腿。某一分钟空簿、冷门、远离平值，均不足以证明该合约长期无研究价值。已到期合约退出当前订阅，其历史仍用于回测和结算核验。

## 4. 应精简或取消的长期记录

### 4.1 保留信息，取消重复表示

| 当前内容 | 建议 |
|---|---|
| 每合约每秒复制 platform、maintenance、lock、lifecycle epoch/确认时刻 | 平台、指数或连接作用域共享保存，合约引用对应有效区间；持续存活确认也要保留，不能只记 open/closed 变化 |
| 60 槽重复规则 hash、规则发布时间、市场状态时间 | 保存规则/状态版本及真正被知悉、采用的时间，秒级状态用起始值＋变化点表达 |
| 最近 snapshot、连接代次和确认时间反复展开 | 基线/恢复事件和连接健康区间保存一次，保留合约独立就绪状态，避免把所有合约当成同时恢复 |
| 64 字符摘要、批次身份、多处重复成员摘要 | 评估完整 32 字节摘要、短引用和去重。保留稳定批次身份及完整性验证，空间收益以真实重编码实测为准 |
| 相同目录内容被反复保存 | 内容版本与观测分离：内容未变可复用，但每次成功复核仍保留时间、范围完整性和来源 hash |
| 各分片重复的同一指数观测 | 身份、内容、可用时间和连接语义相同才合并为共享事实；不同观测不能假装同步 |

当前 `options_catalog_quality_evidence_minute` 主要保存“每秒指向哪些已存在的状态事实”。未来可取消这张逐合约展开表，改为共享事件及合约状态区间；保留它表达的交易状态与知悉时间。

commit 仍有必要，因为事实跨表写入可能只成功一部分。可以减少重复摘要，但必须保持预期成员、预期差量和提交可见性。若仅保留总摘要，单合约查询不能凭总摘要自行宣称已经核验：要验证全批，或保留可验证的成员摘要/证明。最终方案需同时量读取成本，不以“少一列”为唯一目标。

### 4.2 不必永久保存的排障明细

1. **逐合约逐秒的精确 `captured_times`。** 它记录冻结完成的微秒时刻，主要用于检查 250ms 截止和排障，不进入收益公式。建议永久保存采样是否准时、无效原因、采样规则版本及异常区间；精确延迟明细可短留。这样不能再对旧数据任意重算新的微秒延迟阈值，属于明确放弃的诊断能力。若仍要求逐字段历史等价，则保留相对采样秒的整数微秒偏移，先做无损编码实测。
2. **每秒最后一个 `change_id`。** 逐消息序列校验继续在线执行；长期保留断档/恢复事件和有效性。每秒末一个 ID 本来就无法恢复该秒全部源消息，不能重新证明完整 WS 链。详细末序号可短留，或在无损版本先做差分编码。
3. **每秒买卖档数的独立副本。** 有效秒可从回放盘口精确计算；无效秒档数不参与机会计算，可归入短期诊断。用批次内容完整性保护盘口，不能在取消档数校验时顺带取消丢行检测。
4. **重复的运行过程信息。** 进程/分片分配、细粒度连接与队列诊断采用有界保留；长期保留采集范围、生效区间、缺口原因。plan/run 当前日量很小，优先级低于上面的大列。
5. **已从事实确定性派生的副本。** BBO、mid、价差、累计深度可查询生成。只有来源与模型确定时才可重算 IV/Greeks；交易所发布的模型值是独立观测，不能声称仅靠盘口就能原样复算。

这些建议改变未来长期保存契约，不等于现在直接清掉旧列。旧摘要包含这些字段；迁移应保留旧格式读取，或建立明确的新摘要与验证记录，不得伪造旧摘要仍成立。

## 5. 暂不需要增加什么

- **全量 IV、Greeks、OI、逐笔成交：** 平价、box 和简单无套利边界优先级低。OI/成交可辅助活跃度筛选，不能代替盘口可成交数量；明确做波动率、maker 成交或动态对冲研究时再补对应输入。
- **原生 combo 全市场深度：** 作为后续独立扩展。单腿历史不能证明原生 combo 当时的报价、成交和优惠资格，也不能给独立下单的组合直接套 combo 费率。
- **重新保存原始响应文件：** 已提炼的定类型事实和来源 hash 继续入库；不恢复此前删除的原文归档。hash 不能补回原文，更不能补回断线期间的新数据。
- **另一套同频 BBO/mid 历史：** 当前 L2 已包含这些信息，没有明确查询瓶颈前不增加永久副本。

## 6. 反而需要补齐的关键输入

1. **版本化费用。** maker/taker、计费基数、上限、适用档位及条件、到期交割费和豁免。当前 metadata 解码结构没有持久化 maker/taker commission；仅在原始样本看到这些字段不代表数据库已采到完整费表。公开费表用于研究情景，账户实际档位由交易项目核验。
2. **精确结算规则与最终结算事实。** 指数、结算采样窗、币种、期权生成同到期期货后的净额流程、实际最终交割价及规则有效期。`settlement_semantics_id` 当前只是经济族标识，代码明确不代表费用/窗口已验证。
3. **资本与融资口径。** 公开保证金、组合抵销、抵押品折扣、借款/资金成本和实际付款/可用款约束；涉及保证金历史模拟时按该模型补 mark 等输入。不能把权利金收入全当作可随意取走的钱，也不能凭名义杠杆给所有期权组合统一算收益率。
4. **必要兑换/对冲腿。** BTC/ETH/USDC 计价利润如要换成 USDT 收益率，需要对应可成交价格和成本。币本位平价或经期货对冲的 box 可能锁定币数量，并未锁定 USDT 终值；还须证明利润与保证金资产在相应期限的兑换/对冲现金流。否则只输出币种收益和按当前汇率折算的情景收益率。BTC 指数只能表示估值，不能证明可以按指数成交。当前未覆盖的腿应标未知，而非按零成本补齐。

官方规则核验：Deribit [费用说明](https://support.deribit.com/hc/en-us/articles/25944746248989-Fees)区分交易、组合优惠和交割收费；[线性 USDC 期权说明](https://support.deribit.com/hc/en-us/articles/31424932728093-Linear-USDC-Options)说明到期生成期货并结算及净额处理。这些都是净收益输入，不能用一个费率常数和合约到期时间完全替代。本次只核验需求，不新增采集任务。

## 7. 深度、频率、覆盖和容量

此前按 2,822 个期权、完整每秒采样外推约 **6,948.5 MB/天**，盘口约 **2,157.4 MB/天**，辅助记录约 **4,791.1 MB/天（69%）**。这是短样本外推，不是当前版本完整一天净增长；69% 也不等于都能删除。来源见[容量比较](../../../research/2026-10-06-current-depth-comparison/report.md)。

已有累计列测量中，期权/交割共用质量表的 `captured_times` 占压缩列量约 **42.44%**，五个状态位图合计仅 **0.06%**。微秒变化值及摘要是重要开销，不能仅凭“60 槽数组看着重复”推算节省量。这个占比包含历史和交割，与纯期权 MB/天不能直接相乘当精确日量。依据见[已有列测量](../../../research/2026-10-07-data-value-audit/storage-inventory.json)。

本次新增只读抽查了 2026-10-06 14:57–14:59 UTC 两分钟，共 2,822 个纯期权、338,640 个有效合约秒：

| 状态 | 有效合约秒占比 |
|---|---:|
| 双边空簿 | 0% |
| 只有单边 | 4.58% |
| 双边有报价 | 95.42% |
| 买卖各至少 5 档 | 79.17% |
| 买卖各至少 10 档 | 4.87% |

因此不能将日量大归因于大量空簿。这是两个健康分钟的档数统计，不是全历史流动性判断，亦未在本次逐秒重新回放；不能据此保证某资金规模的成交容量。

同一纯期权样本中，epoch、最近 snapshot、规则发布时间、市场状态时间、规则 ID 等在全部 5,644 个合约分钟内均未变化，适合起始值＋变化点。反之，`captured_times` 每分钟 60 值全部不同，仅改成变化点没有帮助；连接确认时间的分钟内不同值中位数为 27，也不能当作连接建立时的一条固定记录。来源时间、接收时间、末序号的不同值中位数为 22。见[统计摘要](../../../research/2026-10-07-options-data-review/profile-summary.json)、[聚合结果](../../../research/2026-10-07-options-data-review/profile.json)和[只读查询](../../../research/2026-10-07-options-data-review/profile.py)。

- **档数：** 5 档可作为之后的默认研究深度选项，但只证明 5 档内的可见容量；不足则缩量或标为未验证。此前期权 10→5 仅预计少约 **65.5 MB/天（0.94%）**，优先级低于质量记录精简。当前仍为 10 档，此前授权只是估算。
- **频率：** 暂保留 1 秒。期权多腿偏价可能短暂存在，改为分钟会丢失同刻价差与持续时间；不能因资金费策略慢就把期权一并降频。1 秒公开 L2 也不能证明多腿同时成交或 maker 排队成交，候选仍需实时验证。
- **覆盖：** 继续保留已配置四族的全部挂牌/到期发现，不按眼前无利润、单边或远翼删流。今后若分成“全链 BBO＋候选深度”，须承认候选外历史深度缺失及选择偏差；本次不建议先做这一步。
- **历史：** 不建议删除唯一盘口历史、已到期历史或亏损时段。它们用于机会频率、持续时间、失败条件与结算检验。历史辅助记录如要清理，先验证新表示及新旧读取，再处理已迁移范围。

## 8. 建议的下一步

先以真实活跃、静默、断线恢复和新挂牌样本，分别测两种方案：A 保留全部信息、改变编码/共享方式；B 在 A 基础上取消非必要诊断的永久明细。两者分开报告压缩后 MB/天、查询时间以及失去的能力。

随后再选定新契约和改造读取器。验收至少包括每秒盘口/缺失状态一致、规则与状态的知悉时间一致、部分写入仍不可见、删除差量仍报缺失、重试身份稳定、旧 10/50 档历史仍按各自格式回放，以及新旧数据计算的候选和可见容量一致。之后才能迁移和清理历史辅助记录。

费用、结算和资金口径作为独立的小规模补采事项安排。当前无需把所有潜在期权研究字段都塞进采集器。
