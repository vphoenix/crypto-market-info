# ARB-0009：期权公开数据采集设计

日期：2026-09-21。版本：R4（按实际采集目标简化）。离线基础与实时采集代码均已实现，公共行情到数据库的完整链路已验证，现有常驻collector已启用期权。配置、查询、验证和启用记录见[实时实现记录](arb-0009-options-live.md)。本版取代 R3 的后续实施范围，旧版保留为[审核历史](../legacy/arb-0009-options-collection-design-r3.md)，不再作为待办清单。

目标是在现有机器和 ClickHouse 上持续保存公开期权数据，供日后分析价差、平价关系及其他套利可能性。目标交付是可运行的采集、存储与回放，不包含自动套利、下单或收益判断。项目不为此新增测试/生产环境划分，也不以连续运行七天作为开始采集的门槛。

以[项目架构](../../architecture.md)、[实际存储字典](../../market-data-storage.md#10-期权采集)和[现有运行方式](../../runtime-operations.md)为约束。代码接入现有collector；启用期权时才初始化相应表。

## 2. 采集哪些合约

先接 Deribit 无认证公共行情，范围为下列四族。名称只供识别，实际身份、到期及单位以已校验元数据为准。

| 合约族 | C/P 期权 | 同到期期货 | 行权价币种 | 权利金 / 结算币 | 指数 |
| --- | --- | --- | --- | --- | --- |
| BTC 币本位 | `BTC-<expiry>-<K>-C/P` | `BTC-<expiry>` | USD | BTC | `btc_usd` |
| ETH 币本位 | `ETH-<expiry>-<K>-C/P` | `ETH-<expiry>` | USD | ETH | `eth_usd` |
| BTC 线性 | `BTC_USDC-<expiry>-<K>-C/P` | `BTC_USDC-<expiry>` | USDC | USDC | `btc_usdc` |
| ETH 线性 | `ETH_USDC-<expiry>-<K>-C/P` | `ETH_USDC-<expiry>` | USDC | USDC | `eth_usdc` |

一次运行固定明确的合约清单。`OPTIONS_SYMBOLS=auto` 在启动时为每族选一个剩余2–45天的近期到期日、平值及两侧各一个实际行权价，C/P成对，加一条同到期期货：共24个期权、4个期货。auto缺少任一族或完整配对时报错重试，不静默缩减；也可配置较小的完整配对清单。

可在启动时用对应交割期货的新鲜双边报价中价选择最接近的行权价，并保存参考报价、源时间与接收时间。用实际存在且C/P齐全的相邻行权价，不假定间距相同；期货必须匹配基础币、结算币、到期及结算语义。参考缺失或过旧时不猜测平值位置，可使用已明确指定且校验通过的清单。

相邻C/P与期货便于日后检查平价及垂直价差。当前支持最多32个合约，可在此范围内调整期限和行权价。更大范围需先测量容量再修改上限；约216个期权不在当前配置能力内。原生combo要另行验证真实腿结构和数量单位，当前不要求为了启动采集而接入。

## 3. 必采字段与扩展字段

| 数据 | 必采字段与用途 | 获取/保存频率 |
| --- | --- | --- |
| 合约元数据 | exchange、symbol、native ID、creation time、market type、base/quote/settlement currency、expiry、C/P、strike及币种、linear/reversed、index、结算语义、native amount单位、contract_size、固定存储精度、定义hash | 启动获取；所选范围定时复核，经济定义变化建新身份 |
| 交易规则与市场状态 | tick及分段tick、最小数量/步长、active/state、观测/知悉/生效时间与依据、来源URL和payload hash；规则单独版本化 | 启动及定时复核；变动时新增记录，失败保留明确未知/陈旧状态 |
| 所选期权和期货 L2 | 买卖价格Int64 tick、数量UInt64 lot，各侧最多10档；`stored_depth=10`、valid/delta位图 | WS维护本地状态，每秒采样；每分钟快照与秒级差量 |
| 行情质量 | 采样时间、真实源时间、接收/完成时间、连接代次、change_id、最近snapshot/连接确认时间、规则引用与发布时间、市场状态依据、有效/缺失原因、实际档数 | 随每秒盘口保存，按分钟60槽打包 |
| 对应指数 | index ID、价格Decimal、源/接收/采样时间、来源时间依据、有效/缺失状态 | 每秒采样，使用独立定类型观测；失败不使正常L2失效 |
| 本次采集范围 | run ID、起始时间、配置、所选instrument及角色、选择依据、参考报价与时间、元数据来源证据 | 每次启动保存一次；每个实时分钟引用本次run |

BBO可直接从已采L2提取；未选合约的全链BBO是额外发现数据，不作为启动依赖。来源缺少时间时保留NULL并明确使用接收时间，不能把采样时间冒充行情更新时间。

按需增加的内容：

- IV、Greeks、mark、OI、成交量及模型underlying：每5秒采样，Decimal加明确单位及来源时间；不是可成交价格。
- 最终交割、公开费率及结算规则：独立低频定类型记录，带采集/生效时间、来源URL和payload hash。未知费用不能按0参与未来净套利判断。
- 保证金公式、组合折扣、全链BBO及原生combo：确有分析需要时再实现；不预建通用规则引擎或额外空表。

低频实时来源必须严格解析、核验本次请求范围的完整性，并保存原始响应hash。失败不能生成貌似更新的事实。不同来源各自记录失败，已经验证的盘口可继续采集。

## 4. 最小运行链路

```text
启动读取配置与所选范围元数据 → 登记规格/规则与本次合约清单
Deribit公共WS → 协议解析 → 精确标准化 → 本地完整订单簿
  → 每秒冻结前10档及质量 → 分钟批量写入 → 查询/回放

指数与低频元数据 → 独立定类型采集 → 批量写入 → 历史查询
```

适配器只处理来源协议。选择哪些合约由配置/启动选择逻辑决定；采样和分析逻辑不塞入适配器。

使用现有机器、ClickHouse实例及采集服务方式。同一数据库的instrument登记和采集写入仍由一个collector负责，避免并发分配身份；期权作为该进程的独立任务启停。实际接入时更新[运行说明](../../runtime-operations.md)，不提前声称服务已启用。

已有离线接口只接受fixture/synthetic。实时接入需增加真实来源的run和分钟发布语义，不能把真实行情标成合成数据，也不能仅放宽离线origin校验就称为完成。

## 5. 固定清单与元数据更新

一次run固定合约成员，从下一个完整UTC分钟开始。启动先核验配置所需的option/future请求范围，保存各响应URL、请求窗口、hash及数量；分页必须完整，合法空集合与请求失败分开。无需先完成与本次范围无关的combo及全链目录。

所选元数据每30分钟复核，盘口连接重建时提前复核。一次目录遗漏不直接判定下架；将受影响合约标为metadata_uncertain，一分钟后重查所选scope。明确到期、关闭或定义冲突后保留原因，不再输出貌似可交易的有效状态。其他合约不受单个对象失败拖累。

经济身份包括交易所、市场类型、标的、结算币、到期/行权价、源身份及经济版本。tick/min amount变化只新增交易规则，不改instrument。源ID复用、数量单位、payoff或结算语义改变需要新身份，不能让旧ID的历史数值改变含义。

目录与规则先写成功，再由有序处理入口发布给采样器；保存实际发布时间，未来才收到的状态不能倒填过去。没有持续生命周期订阅时，市场状态必须标明基于最近目录观测，不能宣称实时确认；断线或收到冲突信号后重新核验。生命周期频道可后加，仍遵守同样的时间规则。

增减成员、换到期日或切换经济身份时，结束当前run并以新清单启动；跨越的不完整分钟和缺失时间如实记录。先不实现运行中自动移动平值中心、预热和无缝换期。记录一次启动对应的实际采集范围，足以解释历史覆盖。

## 6. 必须保留的数据正确性

### 6.1 精确数值与数量单位

复用已实现的固定价格/native amount存储单位 `0.00000001`。原始数字字符直接转Decimal，再精确转Int64价格tick和UInt64数量lot；拒绝舍入、溢出、非法数值与冲突字段。金额、比例及费用不经过float64。

来源下单tick与存储单位分开，规则变化不能重解释历史价格。盘口quantity保存native amount，`contract_multiplier=1`；`source_contract_size`独立保留。基础币数量、反向期货USD面值、combo单位分别处理，不能直接比较不同市场的qty_lot，也不能再重复乘contract_size。

空边/空书可以是有效状态。单腿价格必须正；已有combo模型支持零/负价。价格0不是空档，只有差量数量0表示删除。沿用已写好的经济规格、规则和组合腿模型，不为本次简化重做表。

### 6.2 连接与订单簿

使用 `book.<instrument>.100ms` 的snapshot/change与前驱校验，维护足够深的本地状态后截取10档。grouped 10档视图没有同样的前驱证明，不替代连续增量簿。[完整频道](https://docs.deribit.com/subscriptions/orderbook/bookinstrument_nameinterval)、[grouped频道](https://docs.deribit.com/subscriptions/orderbook/bookinstrument_namegroupdepthinterval)

ACK仅表示订阅确认。首次snapshot建立基准；只有prev_change_id匹配才应用change。断档、冲突重复、解析错误或队列丢失均先使相关书失效，再重订取新snapshot。旧连接代次的ACK/消息不能覆盖新状态。

连接级心跳与退避重连用于恢复采集。冷门合约没有变化不等于断流；心跳也不能刷新该合约真实源时间。共享限频、服务端冷却和有界队列即可满足起步需要，不按每条行情写数据库。沿用单书每侧20,000档保护；超限标无效，不能静默截尾后继续声称状态完整。

### 6.3 每秒截止与分钟回放

用一个有序处理入口串行接纳行情、规则/目录更新和采样边界；多WS接收任务也先进入该入口。分配接纳时间/序号与入队是同一个原子步骤，边界不能越过尚未入队的较早事件。新事件接纳时间越过秒边界时，入口先补入该边界再入队新事件；静默时由定时器通过同一入口推进边界。处理发生延迟不改变事件所属秒。

采样T仅使用不晚于T接纳的行情、已发布且生效的规则和当时可知的市场状态。一个处理循环按顺序处理边界并冻结前10档。数据库写入异步批量进行，不能阻塞排序入口。沿用250ms完成宽限，逐成员检查实际冻结完成时间；迟滞秒记无效。入口队列溢出或时钟跳变会结束当前run、丢弃尚未完成的分钟并重启采集，形成可见时间缺口；不能读取更晚当前书填回T秒。

每分钟第0秒保存完整前10档及 `stored_depth=10`。第1–59秒按价格保存相对本分钟上一个有效状态的最终差量；同秒同价多次更新只保存采样时的最终数量。第0秒未知则本分钟不可回放，但继续保存质量；已知空书可以作为有效起点。

`valid_bitmap`区分无变化与无效，`delta_bitmap`标记应存在的差量。缺应有行返回incomplete，不把丢数据解释成无变化。旧50档仍按原stored_depth完整恢复，不先截为10档。

## 7. 存储与查询范围

已实现的六张表和字段以[存储字典10.1](../../market-data-storage.md#101-已实现的离线基础表显式初始化)为准，均保留：

- `derivative_contract_spec`、`derivative_trading_rule`；
- `derivative_book_minute`、`derivative_book_second_delta`、`derivative_book_quality_minute`；
- `derivative_book_foundation_commit`：仍只发布离线fixture/synthetic数据。

实时实现新增四张表：`options_live_run`、`options_metadata_observation`、`options_index_minute`、`options_live_minute_commit`。run以一行定类型数组保存实际配置与成员；分钟提交保存run、minute、batch ID、实际成员摘要和期望行数，先数据后标记，重试复用原内容。复用原盘口事实表及编码；真实与离线批次使用不同提交表和读取入口。

元数据证据按请求范围保存来源URL、scope、请求窗口、来源/采集时间、payload hash及结果。当前规则/定义引用和新元数据响应hash分开，后续复核不覆盖首次经济定义的来源证据。写失败的半批不能被查询视为完整。

不因R3曾列过表名就全部创建。独立option/combo子表、全链quote、完整analytics、fee/margin和动态universe表当前均不是要求；已有规格表的typed字段已能表达的内容不重复拆表。新增实时表的物理字段随实现同步到存储字典，不使用通用JSON大表。

只读检查先支持：查询本次成员和有效/缺失比例、回放任意历史秒、查看相关规格/规则与指数。回放返回SampleTime与真实SourceTime、连接/缺失状态及batch/run身份，不把查询时间当来源时间。日后分析多腿时按UTC秒和合约单位组合，只报告10档内可覆盖的数量；缺腿、缺成本或指数不等价要明确标出。

## 8. 完成标准与运行检查

实时代码已接上公开来源并能查询真实历史数据；持续运行使用现有collector的配置开关。正常停止保留已经提交的数据，并限时写完排队的完整分钟，不提交末尾不完整分钟。

完成时验证：

1. 真实C/P及同到期期货经过连接、解析、采样、写入和只读回放；实际采了哪些成员可查。
2. 数值精确、60秒逐秒恢复、数量0删除、10档边界补入、空书/无变化/缺失和断档重建测试通过；旧50档回归保留。
3. 模拟重连、采样迟滞、规则晚发布、数据库写入失败；失败期间不产生假有效数据，重试不改身份。
4. 启动真实采集后检查最新完整分钟、有效比例、源时间、连接重建和写入错误；问题可定位到具体来源与成员。
5. 在实际采集过程中记录活跃与低活跃输入的压缩空间及查询耗时。少于一天只报告观测窗口和日量估算，积累满一天后记录实际日量；这项测量与持续采集并行，不要求先等七天才开始收数据。

可用空间、内存/队列峰值和API限频按本机实测调整。出现超限就明确报错或停止受影响任务，不悄悄减少档数、丢弃配对腿或伪造完整数据。不设置固定的“两小时探测→七天试采→生产集成”审批流程。

单collector、旧二进制不识别option类型这些现有约束仍需遵守。接入同库前更新到能读取新类型的构建；停止期权任务后也须保留该兼容性，不能删除历史instrument来迁就旧代码。这是现有程序兼容要求，不是新增一套运行环境。
