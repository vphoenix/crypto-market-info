# ARB-0009 R5 持续运行修复

本轮针对已部署自动发现程序的持续运行故障。2026-10-04首次验收只覆盖启动后的几分钟：目录能发现新合约、计划能提交，不能证明到期通知突发、重连和证据刷新后仍持续有效。作者和独立审核都遗漏了这些组合场景，首次修复未完成到可靠运行的程度。

## 已核验的故障

[生产复查](../../../research/2026-10-04-postdeploy-status-2224/report.md)记录：北京时间16:00真实到期期间出现13,397次重试容量拒绝，之后长期状态屏障未完成；最近完整小时只有0.35%的计划成员秒有效。22:40计划2,977成员，实际提交2,848成员，仅6个整分钟有效；公开目录还有113个open合约停在waiting_open。16:39起出现`wrong catalog state evidence`，不能以进程运行认定采集正常。

实现缺陷包括：状态通知逐条持久化且队列/重试容量不足；拒绝后没有主动确认丢失屏障；creation覆盖开市状态、WS源时间与HTTP接收时间混用；目录仅刷新规则引用，状态引用35分钟后过期并导致分片写入失败；退役逐条退订耗尽控制队列。复审另发现新epoch状态恢复与序号隔离、未知新增/terminal成员恢复、慢ACK和历史频道使用导致的连接容量恢复边界。

## 修订行为

生命周期按128条合批，逐条不可变身份和来源保留；拒绝后有界的symbol屏障会触发fresh单合约确认。创建、开市与重连按epoch和接纳序号确认，WS时间只与同epoch源时间比较。规则和状态证据各自计算新鲜度，采样器提前标记无效，writer仍严格校验引用。目录刷新可续期已确认的目录状态。到期停止确认工作，成员移除合批退订并等待ACK，冷却与连接容量不足时保留恢复意图。

语义细节见[存储文档第10.4节](../../market-data-storage.md)。只覆盖期权链路，没有包含共享工作区其他采集程序的未部署改动；候选以原生产隔离源码加明确的修复文件构建。
