# JustLend Keeper：动态 40＋10 检查设计

日期：2026-10-24（UTC+8）。状态：**设计及实现已完成；实际部署和验收见[实现与运行](justlend-keeper-dynamic-selection-implementation.md)。**

用户已确定每轮最多检查 50 个租约，其中 40 个重点检查、10 个探索检查。本文记录已批准设计；后续实现和上线由用户另行授权，实际状态见实现说明。范围仍是公开数据采集、排序和只读模拟，不签名、不广播、不使用私钥。

本设计替代固定 50 个样本作为机会检查范围，也替代 `codex/keeper-opportunity-probes` 的研究/机会 1:3 调度。该分支提交 `95e678195` 已有当前租约观测、条件模拟和奖励认证，可作为实现依赖；它尚未合入本次查看的 `main`（`1aacedc35`）。依赖整合时必须重新验证，不能把设计描述当作已有功能。

## 1. 已确定的决策

| 项目 | 决策 |
|---|---|
| 50 的含义 | 一轮最多准入 50 个不同订单身份，不是候选总数、RPC 次数或并发数 |
| 40 个重点名额 | 在当时可检查的订单中，按可解释的风险代理排序；不声称已知真实获奖概率 |
| 10 个探索名额 | 从等待最久的可检查订单中选取，不是排序第 41～50 名，也不是每轮重新随机 |
| 调度顺序 | 重复十次「重点、重点、重点、重点、探索」，避免探索一直排在轮尾 |
| 候选范围 | 全部已发现的未确认关闭订单；取消按 hash 截取 1,500 个的成员限制 |
| 名单生成 | 每个名额实际准入时重新选择，不在轮开始时冻结 50 个身份 |
| 源请求 | 沿用一个 owner、一个 HTTP 在途和共享每日预算；本次不提高请求速率 |
| 冷却 | 沿用请求间隔及源端冷却；额外以订单级复查时间避免重复无效检查 |
| 旧固定样本 | 历史标识和事实保留；新动态模式不再为它分配独立请求份额 |
| 存储 | 保存实际观测和被选中者的决策依据；不把全体评分每轮写一遍 |

「最优」在本版本中具体指：**优先找到满足清算条件的候选**。它不等同于最大净利润、最高年化或最高抢单成功率。40:10 是用户确定的初始策略，作为版本化配置保存，验收后才能根据证据调整。

## 2. 事实依据与能力边界

官方接口说明区分订单保存的 `amount/securityDeposit/rentIndex` 与 `getRentInfo` 返回的当前押金、当前指数和可清算标志。后者不包含 amount；`liquidatable=true` 也不是执行必然成功。扩展 Rent/Return 事件提供更新后的订单字段。实现必须使用同一订单版本的数据，不能把旧 amount 与另一次续租后的押金拼接。[官方合约参考](https://docs.justlend.org/developers/energy_rental/)、[官方 ABI](https://docs.justlend.org/developers/abis/energy-market.json)。

当前代码已有事件字段和部分当前状态观测，但没有经过完整验证的本地清算模型。**本版本不复制完整清算公式，不根据租约年龄宣布到期，也不把预付金公式当作清算条件。** 排序使用下述公开、明确标记为近似的押金消耗代理；最终资格仍通过 `getRentInfo` 和只读模拟检查。

RPC 服务的限额与账户、接口和政策有关，程序的 40,000 请求/UTC 日是本地总预算，不是供应商承诺。[TronGrid 限速说明](https://developers.tron.network/reference/rate-limits)。本设计不依赖未经测量的高并发能力。

## 3. 候选全集、覆盖与事件更新

### 3.1 身份和版本

订单身份为 `(network, market_contract, resource_type, renter, receiver)`；本次仅 TRON 主网既有市场的 energy=1。

- `lifecycle_id`：可验证的一次从开立到关闭的生命周期。历史起点不完整时允许 unknown，不能凭观察窗口起点杜撰开立时间。
- `generation_id`：最新影响订单状态的规范事件位置及身份的摘要。续租、增加资源、部分归还也更新 generation，但不必创建新 lifecycle。
- 规范位置使用块高、交易序号、收据日志序号和块 hash；仅有供应商位置时标记 indexed-only。冲突或同块无法排序时进入待核验状态，不按时间戳猜顺序。
- 已核验关闭再出现后续开立，重新创建生命周期。旧请求的迟到结果只进入历史观测，不更新新 generation。

### 3.2 全集构建

首次转换从已提交、计数和摘要验证通过的 typed 索引页与事实分页重建。已有 1,500 项缓存和旧 cohort 只作补充线索，不能作全集。读取按完整页/窗口推进，保存转换游标；正常运行只应用新提交页，不能每轮扫历史 SQL。

重建期间维护覆盖起止位置、三类事件的缺口和来源状态。若现存历史只覆盖最近 30 日，则只能称「已发现订单全集」。达到「本市场全部存续租约」的条件是：从可核验的合约部署起点，或可证明完整的状态快照起点，到当前三类事件均连续覆盖。未满足前持续分页回补并明确显示缺口，不把未发现的旧租约算成已关闭。

历史回补、实时页、状态检查使用同一预算；不以获得全集为名先对所有地址逐个执行模拟。分页转换可以从有界本地快照加后续已提交页继续运行，内存不足时分页，不丢弃成员。

### 3.3 事件作用

| 输入 | 对运行态的作用 |
|---|---|
| Rent / 部分 Return | 更新 amount、押金、指数、位置和 generation；旧预测失效，重新计算 |
| indexed-only 关闭事件 | 记为 closure-pending，暂停该旧版本的奖励模拟，安排核验；不永久删除 |
| 已核验 Liquidate / 全额 Return | 关闭对应版本并移出可选集合；保留防止迟到旧事件复活的关闭位置 |
| 重复页或重复事件 | 根据事件身份幂等；不同索引原始行仍保留来源记录 |
| 重组、撤回或相互矛盾的来源 | 相关预测失效；需要有界重放/核验，不能混入已固化状态 |

每个源分别保存完整分页覆盖水位。重点和探索的模拟准入都要求三类实时索引覆盖足够新鲜，默认最老水位距当前不超过 5 分钟；不能用旧固定样本的 EvidenceCursor 冒充动态全集的水位。缺口期间允许索引、核验和恢复，不根据旧状态新发清算模拟。

## 4. 40 个重点检查的排序

### 4.1 输入和公共租金率

每个订单保留最新可信事件字段、最近一次有效当前状态及其来源引用，另存最新尝试结果。失败不能覆盖最后有效值，但会使当前结果变为 unknown；旧值只能按年龄作为估计输入，不能继续宣称当前可清算。

新增共享 `_rentalRate(0, 1)` 只读观测，默认最多每 5 分钟一次：before head → rate → after head。同市场订单复用它，不按订单重复请求。保存严格解析的 UInt256、1e18 定点缩放、请求/响应 hash、UTC 时间、前后区块锚点、实现身份和结果状态。TTL 为 5 分钟；调用失败不伪造新的有效值或推进旧值时间。

该 rate 是**当前每秒租金率**，不是历史实际扣费路径。所有 RPC 都走原预算；公共 rate 任务等待时不得阻塞已具备输入的订单检查。过期或缺失时停用依赖 rate 的重点估计，探索继续。

### 4.2 风险代理的精确定义

选取同 generation 的基础状态：优先最近有效 `getRentInfo` 的押金，否则使用最新事件中的完整押金。amount 必须来自与其匹配的状态版本；缺失、不确定或为零时不计算。事件押金不是增量 `addedSecurityDeposit`。不对缺字段的旧 ABI 填零。

令：

- `A` = 订单资源对应的 delegated TRX，单位 sun；
- `D` = 基础状态押金，单位 sun；
- `t0` = 该基础状态的链上参考时间；latest 非固定状态使用记录的后置头时间，并保留其前后范围与近似标志；
- `r` = 新鲜公共 rate，单位 1e18/秒；`S = 10^18`；
- 先用 UTC 微秒计算年龄并检查 `0 <= now-t0 <= 24h`，再令 `dt = floor((now_us-t0_us)/10^6)`，单位为整秒；该小于 1 秒的截断属于估计模型，不改变保存的来源时间。

```text
remaining_scaled = max(0, D*S - A*r*dt)
pressure_seconds = remaining_scaled / (A*r)
```

`pressure_seconds` 只表示「假设过去至今和未来都采用当前租金率时，押金余量对应的时间代理」，**不是可清算倒计时**，不扣猜测的清算费或储备。它可能偏离真实情况；归零只是提高检查优先级。超过 24 小时的基础状态、r=0、rate 过期、负时间、版本不一致均返回 unknown，不返回 0 或无穷大冒充已知值。

计算用任意精度整数；比较分数用交叉相乘，不经二进制浮点数，也不先截断成整数秒。导出时可附向下取整的秒数和原始输入。中间乘积不能强制截入 UInt256；链上输入本身严格检查 UInt256 范围。

租金指数仍保存为原始观测，但本版本不使用未经验证的指数差公式外推。未来要改成精确计息/储备模型，需另立 estimator_revision，并与合约计算逐项验证。

### 4.3 比较顺序

先过滤尚未到复查时间、已关闭、在途、当轮已选身份、核验重试耗尽、来源全局阻断的订单。

| 优先层 | 条件 | 层内排序 |
|---|---|---|
| 0 | 最近一次有效结果为 true，距观测不超过 5 分钟；无后续失败、generation 变化或实现变化 | 最久未尝试优先，再按稳定订单键 |
| 1 | 已核验当前 origin，且可以计算压力代理 | pressure_seconds 从小到大，再按最久未尝试、稳定键 |
| 2 | 只有 indexed-only 完整字段，且可以计算压力代理 | 同上；选中后先核验，不能直接模拟 |

不具备上述条件的订单进入探索可选集合；重点没有可选项时允许探索补位，并标记实际选择原因。排序只用于请求选择，不输出伪造的成功概率或预期奖励数值。

已知真实 source-time 或块时间相差过大、字段来自不同 generation、实现 code hash 不一致时，不允许靠置信度打折继续计算，必须降为 unknown。

## 5. 10 个探索检查与公平性

探索使用同一个全集，排除当轮已选、关闭、在途、尚在冷却和被隔离的订单，按 `(fair_since, order_key)` 递增选择。

- `fair_since` 初始化为第一次发现的本地 available_at；历史重建使用已保存的真实 available_at，没有时才使用显式重建时刻并标明来源。
- 每次重点或探索准入后都更新为本次尝试时间。事件更新不把它重新置零，新订单也不自动排在所有旧订单之前。
- 查询失败也更新尝试时间并进入冷却，防止一个故障订单长期占探索首位；另外保存 `last_success_at`，避免把尝试覆盖误报为有效覆盖。
- 信息缺失、旧 ABI、过时观测、待关闭/顺序核验都可经探索获得新证据。探索成功后可在下一轮进入重点。
- 核验连续三个 admission 失败后按 generation 隔离，保留原因和统计；新 origin、已批准的 parser revision 或显式恢复才能解除，不能通过出队/重启重置次数。

固定、可检查的 N 个成员，在没有服务故障、源饥饿或冷却阻断且每轮完成 10 个探索的条件下，最迟 `ceil(N/10)` 个完整轮次内获得一次尝试；重点命中会进一步缩短等待。该界限不是成功观测保证，更不是不断增长集合的固定时限。

以先前的 1,226 个候选作容量示例：只有 10 个探索名额时，保守上界为 123 轮。按下面的约 33 分钟/轮估算，可能接近 67 小时。因此 40＋10 有明确的覆盖代价。报告必须展示最长未尝试/未成功时间；默认超过 24 小时显示覆盖超时，不能声称每日全量检查。40:10 不自动改动，后续根据实际覆盖和命中情况调整。

## 6. 轮次与单项检查状态机

### 6.1 轮次

一轮指最多 50 次订单准入，不是固定的 5 分钟窗口。没有可选对象时不创建空轮。开始后保存 round_id、策略版本、计数、已选订单键及进度；每 5 个名额中第 5 个是探索，其余为重点。

1. 根据名额类型选取当前候选；偏好的集合为空时，可从另一集合补位，分别记录 requested_lane / actual_lane。
2. 请求前重新检查最新 generation、来源覆盖、冷却和当轮去重。
3. 将决策与操作意图一起持久化后才发首个请求，此时消耗一个订单名额。准入后的失败、撤销、预算中断都不退还名额，不无限补选凑满 50 次成功。
4. 一项中的 seed、getter、条件模拟和 HTTP 重试不重复占名额，但所有实际 HTTP 尝试计入 RPC 预算。即使在同一轮发生续租，相同订单身份也不再准入第二次。
5. 当轮 50 项已结束、无其他可选项、源被阻断、当日预算不足或轮次持续达到 2 小时，停止新准入并按真实原因进入收尾；已尝试请求先按原规则完成必要尾部证据或标记 incomplete，再结束为 complete / partial。实际 finished_at 可以因存储背压晚于 2 小时，不能丢弃在途操作来满足时间目标。
6. 无任务或等待预算时只计算下一唤醒时间，不循环创建 partial 轮或落盘。跨 UTC 日不补发昨天错过的轮次。

轮中追加的新候选可参加尚未准入的名额。旧的重点名单不会因提前冻结而占位。政策配置在一轮内固定，下一轮使用新版本。

### 6.2 单项流程

```text
准入并持久化决策
  → 必要时核验最新 origin：solid head / block / receipt / transaction
  → 重新检查 generation 与来源覆盖
  → before head
  → getRentInfo
  → 若可信且 true：liquidate 只读模拟
  → after head
  → 冻结并提交观测
  → 更新 last_attempt / last_success / next_due / 估计输入
```

seed 与 rental-state 可保持原有两个 capture，但关联同一 slot_id，由同一 owner 顺序完成；不另开 worker 绕过节流。验证后若仍缺 amount，本轮只保存可用 getter 结果并将预测保持 unknown，不偷偷增加逐订单 `rentals` 全量扫。旧 ABI 的 amount 本身仍可从其已核验事件读取。

`getRentInfo=false` 只表示当次条件未满足；API/TVM 错误、REVERT、解析失败、尾部头失败分别保存，不能统一转换成 false。真实奖励认证沿用依赖版本的实现身份、返回值、匹配日志、原生 TRX 付款一致性要求；缺证据保持 unknown。模拟成功不会自行把订单关闭，只有实际关闭事件能关闭它。

默认复查规则（实现时作为策略版本中的参数）：

| 当次结果 | 下一次最早复查 |
|---|---|
| true 且模拟有完整正奖励证据 | 60 秒后；仍受轮内去重和全局调度约束 |
| false 且压力代理不超过 30 分钟 | 5 分钟后 |
| false 且代理更远或 unknown | 30 分钟后 |
| getter true，但模拟失败、REVERT 或奖励证据不足 | 5、10、20、30 分钟递增，连续同类失败封顶 30 分钟 |
| 网络/API/解析 unknown | 同上；429/封锁采用更长的源冷却优先 |
| seed admission 失败 | 至少 30 分钟；同 generation/revision 最多 3 次 |

新状态事件使估计失效并允许按新 generation 重新评估；源端冷却和账户预算不能被新事件解除。失败后的最后有效 true 不进入优先层 0。

## 7. RPC 预算和时间成本

本次先保留此前实现的限速：研究相关每次实际请求至少间隔 5 秒，每条 seed 或 rental-state 请求链结束后至少 30 秒，单 HTTP 在途；源端限速、启动暖机、40,000/UTC 日总额、Retry-After 和重试计数继续有效。所有新公共 rate 请求也经过共享 gate。这个选择限制了检查速度，后续可独立做实测调整，不把它解释为服务商要求。

采用既有每请求最多三次尝试的上限。每项首次 seed 至多 4 个基础请求，getter 链 3 个，true 时增加 1 个模拟；不含重试最多 8 个。跨 operation 的 slot_id 持久化，不能重启后再次免费核验。

| 50 项一轮，无重试 | 基础请求数 |
|---|---:|
| origin 已核验，全部 false | 150 |
| origin 已核验，全部 true 并模拟 | 200 |
| 全部首次核验，全部 true 并模拟 | 400 |

公共 rate 一次 3 请求，5 分钟一次，理论全天最多 864 次；它和事件分页、身份、报价等另计入同一个总额。不得把 40:10 宣称为 RPC 80%:20%，因为两类订单需要的 seed、模拟和重试不同。

50 个已核验 false 项按原间隔的纯算术下限为 `50×40−30=1,970 秒`，约 **32 分 50 秒**；全部 true 则至少再加 250 秒，约 **37 分钟**。首次 seed、网络耗时、其他任务和写入使它更长。不能标成实测轮次周期或保证捕获短暂机会。

正常优先级：已尝试模拟的尾部证据、实时三类索引、当前项的后续步骤、到期公共参数和新项准入、历史回补。参数不能无限挤占订单，订单也不能饿死实时索引；对就绪的后台类别采用轮转，发现新鲜度门槛失守时暂停新项。暂停期间记录原因，不转而凭过期字段加速模拟。

## 8. 定类型运行态与审计存储

### 8.1 本地运行态

采用单 owner 的分页定类型状态，逻辑上拆成两组：

| 状态 | 内容与更新时机 |
|---|---|
| OrderSummary | 订单键、lifecycle/generation、事件字段、源位置/事实引用、关闭状态；仅事件或核验结果变化时更新 |
| CheckState | 最后尝试、最后有效观测引用、最新结果枚举、next_due、fair_since、核验次数及失败状态；仅实际准入/结果变化时更新 |
| RoundState | 当前 round/slot、最多 50 个去重键、策略版本、不可变决策引用、子 capture 引用；完整决策输入单独保存一次 |
| CoverageState | 三类事件覆盖范围/缺口、重建游标、公共 rate 观测引用、实现版本 |

未知用 nullable/枚举明确表示，不以 bool 默认 false 替代。按订单身份和 generation 保存失败上限，不随缓存淘汰清空。正常运行内存只保留紧凑摘要及排序结构；大集合使用分页缓存，成员数量超过缓存容量不意味着成员被删除。

重点选择初版允许对内存摘要做 O(N) 扫描并用 O(50) 的候选堆；同时维护探索时间序。公共 rate 更新时统一使相关估计失效；只在实际准入前做必要重算，不按秒写新的 score。摘要不能全部常驻时，分页扫描的读取量也必须纳入性能验收；不能因为没有全量 SQL 就宣称没有全量磁盘读取。若实测内存/CPU 或页读取成为瓶颈，再改用紧凑内存索引，不预先增加历史 SQL 的按分值索引。

复用 `PagedMap` 时，持久页的 eligible/oldest 摘要只依赖保存的字段，不能在摘要函数内读取当前时钟，否则同一页稍后重新载入就可能校验失败。`next_due <= now` 在查询/准入时判断；时间推进本身不改写全部页。

### 8.2 新增历史模型（拟议，尚未安装）

已有 rental-state 与 probe 观测继续保存链上结果；采样决策不能混入它们伪装成链上事实。拟新增四张专表：

| 模型/表 | 身份与必要字段 |
|---|---|
| RentalRateObservation / `jl_keeper_rental_rate` | `(capture_id,row_ordinal)`；市场/资源、实现身份、rate nullable UInt256、scale、UTC 请求/接收时间、前后头、API/TVM/status、请求与响应 hash |
| RentalRateBatchProof / `jl_keeper_rental_rate_batch` | capture 身份、行数、定类型编码摘要；空失败批次也有 proof |
| SelectionMember / `jl_keeper_selection_member` | `(round_id,slot_no)`；订单/generation、requested/actual lane、selected_at、reason、估计版本与 nullable A/D/r/t0、输入事实引用/摘要、覆盖引用、状态/子 capture 引用、实际 RPC 尝试数 |
| SelectionRound / `jl_keeper_selection_round` | round_id/capture_id、策略版本、开始/结束时间、配置40/10、实际各类数、终止原因、候选/可选/隔离数、覆盖范围/缺口摘要、member_count/member_digest；兼作该轮 proof |

每个被选中成员保存的是**准入时**的决策输入，不在轮末用新数据重算覆盖。派生分数可以由整数输入重现，无需在数据库存任意精度分数。源 hash、source time 和链上位置通过直接字段或不可变事实引用可追溯；索引来源和独立核验来源必须区分。

轮内决策跟随原操作意图持久化；结束后一次提交最多 50 条 member、round proof，最后提交 capture。引用的子批次须已提交或明确标为未请求/失败/不完整，不将缺引用解释为成功。轮次超时也提交带终止原因的 partial 记录；未结束轮由 checkpoint 恢复，不丢弃其已发生请求。

新批次所有预期为零的成员集合也要读取核验；重复、额外行、digest 不符或相同 ID 不同内容均拒绝。新 kind 使用独立封存编码/验证，不改既有 capture 和成员的冻结摘要。MySQL 与 ClickHouse 都要实现专用映射、DDL 和查询；collector 不自行执行 DDL。导出增加上述 typed CSV，并明确观测与估计的区别。

### 8.3 写入约束

- 不逐轮持久化全量排名，不逐项重写包含全体候选的一个大对象，不新增请求/响应原文归档。
- OrderSummary 与 CheckState 使用独立页根；一次结果只写受影响页、当前轮的少量引用和检查点。现有 `PagedMap` 每页最多 128 项，cacheBytes 是驻留缓存预算，不是页大小。页根描述符会随页数增长，其 checkpoint 开销须单列测量，不能承诺全体运行态写入严格为 O(1)。
- 原请求预算、发送前意图、冻结 SQL 提交及 current/previous checkpoint 的 fsync 屏障保持。减少写入通过只写变化和批量审计实现，不能把预算持久化延后造成重启漏计。
- 全集初次重建会产生一次性读写和 O(N) 当前摘要空间；历史选择记录按实际检查数增长。没有测量前不承诺磁盘负载不变。
- 旧关闭记录可从内存淘汰，但关闭位置/版本证据必须可恢复；当前、上一检查点与未决操作仍引用的文件不得提前回收。

## 9. 故障恢复与兼容

1. 新模式命名为 `dynamic-40-10-v1`，单独 feature flag。先安装并验证新 schema，再显式转换候选全集和 runtime 格式；转换可续跑，完成前不宣称全集准备就绪。
2. 状态绑定实际数据库、采集配置、恢复世代和实现身份，保留原预算、源冷却、未决操作及每日边界；转换不重发 HTTP。
3. 冻结旧操作先按原内容提交；未冻结操作由同一 owner 排空并计入真实请求。完成模式切换后旧固定 cohort 不再产生独立 probe，避免双重预算。
4. 重启后恢复同一 round、slot、generation 和 seed 尝试次数。HTTP 发送与响应之间崩溃可能需要重试读取，记录实际尝试而非承诺网络 exactly-once；数据库冻结批次仍要求身份稳定和幂等。
5. 部分写入失败保持同一 proof/member 重试。数据库不可用不能持续无限消费 RPC 并堆积内存；沿用存储背压。
6. 实现身份变化时停止旧估计/模拟认证，继续公共索引并报告不匹配。新增来源的失败不能伪造其他来源当前状态。
7. 旧二进制不能写新 runtime 格式。回退应使用能够读新格式并关闭动态调度的兼容二进制，或显式受控转换；不能恢复陈旧 checkpoint 丢掉已用预算和在途请求。

## 10. 验收标准

### 10.1 正确性

| 场景 | 必须得到的结果 |
|---|---|
| 连续 50 次准入且两类均有候选 | 40 个重点、10 个探索，4:1 交错，同一订单不重复 |
| 重点/探索一侧不足 | 明确记录补位原因，总准入不超过 50；无任务不生成空轮 |
| 重点排序 | 分数比较用整数；完整输入可重现；零 rate/缺字段/负时间/超龄为 unknown |
| 超过 1,500 个订单 | 没有 hash 淘汰；转换后数量、关闭状态及覆盖可核对 |
| 旧 ABI、同块冲突、源页乱序 | 不拼凑字段；进入探索核验，核验前不模拟 |
| 未选择的订单反复有新事件 | 保持原公平等待位置，不无限推后或抢到队首 |
| 关闭重开/续租/部分归还/迟到响应 | generation 隔离正确，旧结果不覆盖当前订单 |
| false、true、REVERT、网络失败、尾部头失败 | 状态分别保留；unknown 不等于 false/零，true 不等于正奖励 |
| 成功只读模拟 | 不关闭真实订单，不广播，不扣链上账户资金 |
| 重启、超时、日预算耗尽、429 | 轮次/名额/尝试数稳定，真实请求全计数，无补发风暴 |
| 只推进时钟后淘汰并重新加载分页 | 页元数据仍能校验；到期判断正确，无全页改写 |
| 缺页、空页、重复行、篡改、写入中断 | 批次验证拒绝不完整；同 ID 重试内容不变 |
| 稳定全集的公平轮询 | 在明确前提下，每项至迟 ceil(N/10) 轮被尝试；单列成功覆盖 |

### 10.2 资源与效果

- 离线分别以 1,226、10,000、100,000 个摘要测试选择耗时、常驻内存、页缓存未命中和 checkpoint 写入量；这些是测试规模，不是已知实际订单数。
- 相同事件序列、相同实际 RPC/结果序列，对比旧调度与新调度的逻辑写入 bytes、file/dir fsync、数据库写入行数和压缩后每日增长。冷候选不因单纯排序改变；空闲循环写入为零；单项检查不能重写全体订单记录。页根元数据随 N 增长的成本另列，不藏在固定开销中。
- 按活跃/非活跃订单分别报告更新频率、存储量、查询耗时；不以短时整机磁盘速率直接外推此功能成本。
- 分重点、探索、补位报告有效 getter 率、true 率、认证正奖励次数、每次 true/认证正奖励对应 RPC 数、round 时长 p50/p95、最大未尝试与未成功年龄、来源覆盖落后、隔离数。分母为零输出无样本。
- 使用仅在当时已 available 的数据做历史回放，防止事后知道清算结果影响排序；没有历史当前状态时不得杜撰模拟命中率。固定样本对照只用历史/离线数据，不额外启动第二个线上采集器。
- 真实 MySQL/ClickHouse 的 schema/roundtrip、相关 Go/race/vet、checkpoint 故障注入通过后再进入运行验收。设计文件检查不能代替这些验收，也不要求与本次纯文档交付一起执行。
