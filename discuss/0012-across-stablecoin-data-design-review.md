# Across 稳定币中继采集设计审核

日期：2026-10-02。审核者：独立 Agent `/root/across_design_reviewer`。

审核对象为 `docs/across-stablecoin-data-mvp-design.md` 与 `docs/across-stablecoin-data-schema.sql`，以及 `research/2026-10-02-across-design/source-manifest.json` 指向的固定官方源码与部署目录。此次仅审核设计，不修改程序、正文、DDL、数据库或服务。

## 审核结论与适用边界

首版以两链、同质原生 USDC、原始空 message 订单、公开轮询为界是合理的。七张专项小表和一个命令程序不构成过度工程化：六类事实语义不同，capture 负责缺口、批次可见性和重组，不需要另外搭消息系统、通用调度器、索引平台或 Dataworker。

这份设计能够回答“公开订单的费用空间是否足够、用本轮询方式看到时是否仍有可参与的状态、值得优先核验哪些订单”，可以否决明确范围内上限不足的路线。首版不能独立回答“可以稳定净赚多少”：逐单退款归属、回款速度、失败成本、库存恢复价格及实际成交胜率仍可能未知。上限较高时只允许进入少量正样本取证，不能给出适合实盘赚钱的肯定结论。不得把这些缺项当作零，也不需要以全链退款重建作为首版抓数的前提。

初审有三项 P1 与一项 P2，都是小范围文案/报告语义补充，不需增表。现已核对修订文件并全部关闭；修订后复审状态见文末。

## 初审发现

### P1-1：报告提出 2/5/10 秒场景，但采集调度没有明确这些观测

第 4.B 节只明确新发现、独家截止附近与截止后的 probe；第 7 节却要提供增加 2/5/10 秒的可达性结果。当前任务定义会使大部分延迟场景永久缺测，首版最关键的可达性问题得不到预期数据。

最小修正：定义固定起点，例如原始订单首次可用时，以及独家结束后首次可用的开放观察时，安排 `+2/+5/+10 秒` 的后续 probe；通过现有有界任务集合运行即可。记录计划时间和实际请求/完成时间，不把晚到的采集当作准时观测。已知成交、过期可停止，跳过/超预算显式 unknown。不要新建通用定时框架或以邻近 FilledRelay 日志替代状态观察。

### P1-2：停止研究所用收入上限需要选择性求和与明确条款范围

第 7 节使用 `inputAmount - 实际outputAmount` 和“全部公开候选差额上限”作为否决条件，但没有定义负差额和未研究更新条款的处理。中继可以不接负差额订单；若负差额抵消正差额，求出的总和并不是可选择订单的收入上限。首版实时只研究原始条款，其上限也不能否决包含加价更新的整个 Across 方向。

最小修正：每个唯一候选只计一次，保留带符号差额用于分析，但可选择订单的费用空间上限按 `sum(max(0, input - eligible_output))` 计算。original 与已实际验证的 updated 条款分别报告；不把事后更新套到提前的可见时刻。否决结论必须写明两条链、原生 USDC、原始空 message、规定轮询方式等范围。部分覆盖或未验证更新只产生 unknown。

### P1-3：跨 capture 的冲突比较不能包含采集元数据

第 6 节规定重复内容冲突时报异常，但事件/收据行也有 `capture_id`、抓取/可用时间和 payload hash。正常补采同一链上事件会改变这些字段；若逐列比较，合法重复将必然误报冲突，first_seen 也可能取错。

最小修正：定义不可变协议内容指纹，冲突只比较同一事件位置上的规范化链上内容，不包含 capture、首次/本次获取时间、RPC 响应原文哈希等采集元数据。不同 capture 的证据与成员摘要仍各自冻结。first_seen 从 canonical 的真实 live 观测中取最早可用时间，backfill/restart/catchup 不参与历史在线 first_seen；receipt 内容冲突也按规范化交易/收据事实检查。

### P2-1：“新鲜实时来源/新鲜头”需要一个可检查的标准

第 4.B 节依赖新鲜 latest 头，但是没有定义 freshness。RPC 返回的 latest 可能已经落后，或者 probe 使用的是很早取到、很晚才调用完成的 head。

最小修正：manifest 定义有限的 head/观测年龄阈值，保留 head 请求/获取时间与区块时间；超限单列 stale，不当作实时可达性证据。使用同一 hash 锚点并验证 canonical 的要求保持。可用轻量的请求时间加现有 evidence，不需另建链头表，也不需私有流/fast feed。

## 已核对且不构成阻塞的内容

- 六个已归档官方文件的 SHA-256 均与 manifest 一致；固定部署目录中的 Base/Arbitrum SpokePool 与设计地址一致。源码归档不是当前代理实现证明，设计要求实施启动核验实现和 ABI，这一边界正确。
- 固定 `SpokePool.sol` 的 `_fillIsExclusive` 为 `exclusivityDeadline >= currentTime`；非指定执行者须严格晚于独家截止。`fillDeadline < currentTime` 才拒绝，故成交截止允许等号。
- 原始 RelayData 与目标链决定 relay hash；depositId 二元组不足以最终匹配。quoteTimestamp 不属于 relay hash，但 LP 费用研究应保留。空 message 事件哈希是 `bytes32(0)`，不能误用 `keccak256(empty)`；DDL 的协议哈希注释和精确核验要求足够，实施应有固定夹具。
- RequestedSlowFill 状态不等于已付款，ReplacedSlowFill 属于 fast fill；slow fill 不应算自筹库存中继利润。speed-up 更新与原始事件分表、保存当时可见时间，是必要而非额外平台化。
- 成交事件 relayer 是退款地址，可能与交易 sender 不同；fill 的实际数量为 updatedOutputAmount。预先 fill、完整条款冲突、历史窗口删失与实时接入权限均有明确保护。
- refund leaf 没有 depositId，包含聚合地址/金额，还可能混入其他路线与用户退款；离线报告不靠 FIFO/金额巧合归属，这一限制正确。deferred flag 只表示至少一笔失败，不能把整叶全部当未付或全当已付。claim 的 caller 是被扣 accrued credit 的地址，refundAddress 才是最终收款人。
- 初审期间设计者已把 refund 表中的可变实付状态、后补 root/hash/receipt 引用移除。事件表保留不可变字段，实际到账从独立 receipt 与保存的根日志派生，避免“补收据后修改旧事件”和跨 capture 内容冲突。这一简化无需新表，认可。
- Base 必须覆盖适用 L1/operator 费用；Arbitrum 的 L1 成本不能再加一次。未知费制和历史无同期汇率时保持 NULL，不拼出伪历史净利，合理。CEX BBO 仅为估值参考，不能证明链上调仓可执行。
- 官方[费用规则](https://docs.across.to/introduction/fees)说明原链还款的 LP 费为零，因此以此作为明确库存情景合理；不能用来替代实例支持、真实退款金额/速度与调仓价格的验证。官方[索引迁移规则](https://docs.across.to/guides/migration/non-evm/indexers)确认新 bytes32 地址、uint256 depositId 与 messageHash 事件语义。
- 先 raw/facts 再 committed、重复重试冻结 capture、最新 revision 后再过滤 canonical、所有孤立尝试作废、源链孤块不能留下目标链候选，这些均是本任务的数据可信性要求，不宜为“简单”删去。

## 可以暂缓的复杂度

保留当前七表，不加 root/config history 平台、逐单退款分配引擎、Dataworker、签名更新执行器、通用链发现、交易模拟框架或自动交易。汇率 BBO 是辅助估值，可在业务上限/开放状态有正样本后再接；历史 gas 原生单位分布与盈亏平衡成本足以先筛。后续逐单退款取证只抽少量有价值候选，未成功归属就 unknown，不扩大为全链索引工程。

结果：

1. **P1-1 已关闭。** 正文明确定义普通新单/接替单的观察基准及三次真实后续任务；DDL 增加 `planned_for_at`、`target_delay_ms`，保留真实请求/完成时间，迟到超过一秒、预算跳过及已成交取消有明确语义。现有小队列足够实现，不需要新服务。
2. **P1-2 已关闭。** 上限逐单截为非负，原始/更新条款不重复累加，排除范围、未覆盖容量及只能否决明确子集的规则写明。这里的上限始终是成本前空间，不是预估净日收益。
3. **P1-3 已关闭。** 正文和 DDL 均规定只比较规范化链上字段，采集时间/来源/raw hash 不作事件冲突；first_seen 从 canonical live 最早真实可用时间取得。收据可选费用字段允许从未知补到已知，两份已知值矛盾才报错。
4. **P2-1 已关闭。** 正文给出默认五秒头年龄与两秒未来时间容差，配置入 manifest，迟缓/时钟未知来源不计实时可达性样本。需要实际小窗口验证误排除比例，但无需在设计阶段扩大接入系统。

**复审结论：在前述研究边界内通过，没有仍阻止首版实现的设计问题。** 可以按这份设计实现小窗口采集、报告和必要校验，再决定回补与观察范围。七表数量不变；已去掉可变退款标签，未知成本/归属不会混成收益。
